# Use iBUS instead of PWM for the receiver → Leonardo link

Связь «приёмник FS-IA6B → Leonardo» переведена с ШИМ (PWM) на протокол iBUS, чтобы убрать главный источник задержки управления: ШИМ-выходы обновляются раз в 20 мс, iBUS — раз в ~7 мс. Первичная цель — минимальная задержка отклика на стик (планёр, важна реакция); один провод вместо шести и упрощение кода — вторичные выгоды.

## Status

accepted

## Considered Options

- **ШИМ (PWM)** — 6 проводов, по импульсу на канал, обновление 50 Гц. Отклонено: квантование 20 мс доминирует в задержке.
- **PPM** — один провод, позиционно-импульсное кодирование. Отклонено: всё ещё кадровая передача (~20 мс), редко на FS-IA6B.
- **SBUS** — последовательный и быстрый, но сигнал инвертированный UART; на Leonardo потребовался бы аппаратный инвертор.
- **iBUS** — выбрано: один провод, цифровой, неинвертированный UART (прямое подключение к `Serial1` Leonardo), 115200 бод, обновление ~7 мс.

## Consequences

- Обновление каналов ~7 мс вместо 20 мс → ниже задержка управления (основная цель).
- Один сигнальный провод (порт «SERVO») вместо шести; ШИМ-пины CH1–CH6 не используются.
- Не нужны прерывания по изменению пина; убрана зависимость от `EnableInterrupt`.
- Прошивка разбирает 32-байтовый кадр iBUS и проверяет контрольную сумму; невалидный кадр сохраняет последние валидные значения каналов.
- HID-отчёт отправляется только при изменении значения и без `delay()`, поэтому добавляемая задержка минимальна.
